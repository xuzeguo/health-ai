## 1. 目标与一期基线

在一期本机单用户桌面聊天应用上，形成“报告解析→人工审核→正式测量记录→工具查询＋知识检索→有依据的解释”完整链路，实践 Prompt、结构化输出、Function Calling、RAG、LangChain、HITL、工作流 SSE 和评测。

一期已有 Vue 3、Pinia、Fastify、OpenAI SDK、Zod、SQLite，提供会话 CRUD、持久化聊天、停止生成、恢复、流生命周期和安全 Markdown 渲染。一期 105 项测试通过是历史验收记录，不代表二期能力已经验证。

保留一期请求与事件契约。个人历史使用 SQL，知识文本使用 RAG；模型只产生草稿和解释，不直接确认、修改或删除正式健康记录。系统仍限本机、单用户、单进程；无账号、公网部署、医疗诊断、设备同步、开放式 Agent、多 Agent 或跨重启自动续跑目标。

## 3. 首版范围

### 3.1 报告解析与审核

1. 一次上传一个受支持的报告，显示类型、大小限制和第三方处理告知；不承诺任意设备或批量 PDF。
2. 服务端进行实际格式、大小及解码限制检查后创建 processing 草稿，返回工作流与草稿标识。
3. 调用已验证识别路径，输出结构化字段；执行 JSON、Schema、业务校验。
4. 只有可安全审核的输出进入 needs_review；无法识别的字段为空，不用 0 或猜测值补齐。
5. 审核页显示原抽取值、当前修订值、单位、警告和重复报告提示。模型自报 confidence 不作为可信度保证。
6. 用户可保存修订、拒绝或明确确认；确认时再次校验，在同一事务内创建记录并更新草稿。
7. 用户可从草稿列表找回待审核项。页面关闭不删除已保存修订，也不自动确认。
8. 解析中停止、离开当前解析页或断开连接会取消请求；已保存的待审核草稿不受后续断开影响。
9. 进程重启后遗留 processing 标为 failed，错误类别为 interrupted，不自动重发模型请求。

草稿状态：processing → needs_review / failed / cancelled；needs_review → confirmed / rejected。终态不得回退，失败或取消后重试产生新草稿，并可关联原草稿。

原始文件不长期保存在服务端。当前页面用本地文件预览；刷新后仍能审核字段，但需要重新选择文件才能再次查看原图，并校验是否与草稿文件哈希一致。对不上时只允许作为另一个文件重新解析，不能冒充当前草稿来源。长期原图归档不在首版范围。

### 3.2 审核一致性

- 每次修改和确认携带草稿版本，旧版本提交返回冲突，提示重新加载，不静默覆盖。
- 一个草稿最多创建一条正式记录，数据库约束兜底；正式记录只来自用户确认。
- 相同确认请求重试返回已创建结果；已确认后提交不同内容返回冲突。
- 确认前展示日期、核心值、单位及缺失摘要；要求有效测量日期和至少一个有效核心指标。
- 相同文件上传成不同草稿时提示潜在重复，由用户决定是否继续；不自动合并、覆盖或删除历史。
- 首版不提供正式记录的编辑和删除；误确认可追溯，正式纠错功能列为后续独立需求。

### 3.3 个人数据分析

聊天页提供显式“普通聊天 / 健康分析”模式。普通模式沿用一期；健康分析使用独立接口和工作流状态视图，同一会话同时最多一个生成任务。分析中禁止删除会话，切换模式、会话或新建时先取消当前任务并完成对账。

首批工具为 `get_measurement_history`、`get_latest_measurement`、`compare_measurements`。模型必须能真实请求工具，由服务端校验并执行固定只读 SQL。规则可帮助路由，但不能用固定规则冒充 Function Calling 验收。

工具不接受 SQL、任意文件路径或网络地址。时间、指标、行数及结果体积均受限；草稿不进入查询。无数据返回空结果。返回范围被截断时必须显示实际覆盖区间与截断提示，不将部分历史描述成完整历史。

趋势差值、数量、日期选择及单位转换由服务端计算，模型负责解释。区分数据事实、一般知识与不确定性；不足两条可比较记录时不宣称趋势。

### 3.4 知识 RAG 与组合分析

首批仅导入可信 Markdown/TXT，包含指标定义、测量条件/局限和一般运动营养知识；保存出处、版本、章节和内容哈希。不收集来源不明的大规模网页，不将个人测量值写入知识向量库。

提供导入、列表、索引状态、删除和重建。只有完成索引的有效文档可被检索；重建失败仍可使用旧版索引；删除后即使物理清理尚未完成也不得再进入新检索结果。

健康分析按需要执行工具和检索，不要求每个问题都检索。最终回答标注数据区间、指标单位及真实知识来源；来源可定位到已导入文档章节。引用存在和内容支持结论分别验证，不把文档列表当作事实正确性证明。

无知识匹配是正常结果，显示证据不足；检索服务故障显示不可用。若个人数据已查到，可继续提供数据事实并说明知识部分缺失。模型故障、数据库故障或最终生成失败不得伪装成成功回答。

### 3.5 LangChain、Prompt 与评测

- 至少一条完整生产工作流通过 LangChain 组件组合运行；业务依赖项目端口，不依赖框架内部状态。
- Prompt 按抽取、健康分析、知识回答分开，文件版本化，记录变更和对应评测集版本。
- JSON/schema 能力以 P0 为准，Zod 始终在服务端作为最终边界。
- 基础评测、版本记录和错误分类属于首版必需项；可视化评测后台属于增强项。
- 不保存或展示私有 reasoning；日志只记任务标识、版本、计数、耗时和安全错误分类。

## 4. 时间、指标与数据展示

核心指标：体重 kg、体脂率 %、骨骼肌量 kg。体脂量、去脂体重、BMI 等首版作为可空补充字段，不强制每份报告具备；扩展字段只能来自受控白名单。

- 保留原始单位和标准化值；报告未提供的值不推导成“原测量值”。
- 日期支持 date/datetime 精度。仅日期不编造时分秒；默认报告时区 Asia/Shanghai，审核时可确认或修正。
- “近三个月”按用户时区从当前本地日期减三个自然月起至当天止，超出月份的日取该月最后一天；工具返回实际起止日期。
- 比较日期首版采用精确本地日期，不自动搜索附近日期；同日多条按测量本地时间、创建时间、ID 确定性排序，返回被选记录的真实日期和精度。
- 最新工具指最新整条记录，不为每个指标拼接不同日期；空字段保留为空并说明。
- 体脂率变化使用“百分点”；相对变化百分比单列，基线为 0 时不计算。
- 图表只用正式记录，缺失不补零、不自动连线跨越缺失点；列表显示来源、日期和单位。
- 跨字段矛盾可分硬错误与人工复核警告，不因正常舍入误差拒绝报告。

## 5. 工作流可见性、恢复与隐私

前端展示阶段、工具名称、查询指标/区间、数据点数、检索来源和回答增量，不展示工具原始参数片段、完整工具结果或报告正文事件。

每个工作流有唯一 ID、请求 ID、严格顺序和唯一终态。回答增量必须先落库再展示，终态必须先提交再发送。刷新后恢复正文、任务状态和来源，不要求恢复全部动画时间线或从断点继续生成。

生成请求结果不确定时仅通过请求 ID、工作流 ID、草稿列表等只读接口对账，不自动重发 POST；确认请求可按已定义幂等语义重试。

上传和解析有字节、像素/页数、耗时、并发限制；临时文件成功、失败、取消均清理，启动时清理进程崩溃遗留文件。Key、Base64、报告正文、完整对话和工具结果不进入日志及验收报告。已有 `.env` 不打印、不覆盖。

非法工具及非法参数离线测试拒绝率 100%，受控有效请求执行正确率 100%；模型是否选对工具另设真实样本统计。这些小样本目标不代表对任意报告或知识问题的准确率承诺。
