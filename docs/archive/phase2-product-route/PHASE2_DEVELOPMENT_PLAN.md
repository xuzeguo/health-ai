## 1. 审查与执行边界

当前只完成设计修订和计划，不安装依赖、不写实验或业务代码、不调用真实模型、不升级数据库、不提交或推送 Git。用户通过本轮审查后，才可从 F02-P0 开始实施。

设计审查通过不等于供应商能力验证通过。P0 完成后以报告和 ADR 收敛输入路径、模型、Embedding、向量存储、LangChain 版本及预算；验证失败涉及范围、额外付费服务或验收目标变化时，提交具体变更供用户审查，不能默默降低验收标准。批准范围内的常规任务与测试自主推进。

一期 P0…P6 已完成；本计划统一使用 F02 前缀，不重新执行一期全套立项流程。阶段结束更新对应文档和任务表，不自动提交 Git。

## 2. 范围和估算

首版包括一条经验证的报告识别路径、1–2种模板、三个核心指标、草稿审核、三个只读工具、可信 Markdown/TXT 知识库、单一 Embedding/向量存储、至少一条 LangChain 实际链路、v2 SSE、结果恢复与质量基线。

不包括长期原图归档、任意复杂PDF、批量报告、正式记录修改删除、多用户、公网部署、分布式锁、完整事件回放、跨重启继续运行、LangGraph 和开放式 Agent。

## 3. 任务拆解与退出条件

### F02-P0：先验证能力，不实现业务

| 任务 | 工作内容 | 验证产物 |
| --- | --- | --- |
| P0-01 | 使用合成数据验证 JSON、Schema、空/截断结果及结构修复边界 | 模型/参数/样本/结果的能力矩阵 |
| P0-02 | 单/多工具、tool消息、流式参数片段、取消与EOF | 原生协议实验及安全摘要 |
| P0-03 | 报告图片或PDF/OCR路径，对比1–2种模板；确认像素、页数、费用 | 明确支持与不支持输入，不以文本原型冒充图片验收 |
| P0-04 | 中文Embedding与一种向量存储，验证维度、持久化、删除/重建 | 选型ADR，明确重建和备份方式 |
| P0-05 | 锁定LangChain版本验证模型、工具、输出、检索和signal | 适配结论与降级方式 |
| P0-06 | 准备至少20份报告、30个知识问题的分层样本清单及标注规则 | 评测分母、质量目标、初始成本与调用预算 |

退出：每项能力有成功/失败边界，识别/文本分析/Embedding分工确定，供应商与依赖版本可追溯；核心能力未通过时不进入假定该能力可用的业务开发。只保留最小实验，不同时维护多套生产框架。

### F02-P1：先把一期与二期接缝做稳

| 任务 | 工作内容 | 关键验证 |
| --- | --- | --- |
| P1-01 | 一期迁移基线、版本/checksum、新实体与索引 | 空库/旧库/重复启动/失败回滚 |
| P1-02 | 共享ConversationTaskRegistry、删除检查和关闭协调 | 新旧同会话互斥、启动失败释放、旧任务不能释放新占位 |
| P1-03 | 模型端口及LangChain骨架，Prompt版本、抽取/审核Schema | 文本/tool两种结束、reasoning丢弃、Schema拒绝 |
| P1-04 | v2信封、独立解码器/useWorkflow、requestId对账、最小run元数据 | 模拟流顺序、唯一终态、未知结果不自动重发 |
| P1-05 | 版本化评测运行器、步骤/上下文/调用预算 | 安全摘要不含正文，预算能触发受控失败 |

退出：模拟工作流贯通创建→增量落库→终态→GET恢复；一期接口不变；共享占位、迁移和关闭回归通过。P1只对未来阶段共用的必要设施建骨架，不提前实现全部产品功能。

### F02-P2：报告到人工确认的独立闭环

1. 实现单文件multipart、实际格式/尺寸检查、随机临时目录、并发限制及CPU密集解析隔离。
2. 接入已验证识别路径，生成processing草稿，JSON/Zod/业务校验后保存needs_review。
3. 实现草稿列表/详情、版本化PATCH/reject/confirm及数据库唯一约束。
4. 实现审核页、当前页面原图预览、刷新后重选文件哈希核对和重复报告提示。
5. 实现基本正式记录列表；取消、重启恢复和临时文件清理贯穿所有路径。

退出：可演示“上传→修正→确认→正式记录”；未审核写入数为0；相同确认重试同结果；旧版本/不同确认内容冲突；刷新可找回，重启无永久processing。覆盖AC-02/03/04/12/16/17及AC-20的日期单位部分。

### F02-P3：真实工具调用与个人数据解释

1. 固定SQL和指标映射，完成history/latest/compare及时间、空值、截断语义。
2. 服务端计算差值和百分点，返回实际记录和范围；使用合成记录验证。
3. 实现工具注册/执行、参数片段聚合、轮次/调用数/字节预算和受控错误。
4. 接入LangChain工具消息循环与最终答案流，工具选择期间不泄露中间正文或推理。
5. 独立分析入口与普通聊天模式切换，共享会话占位；初版工具状态视图。

退出：真实模型按问题选择工具并解释测试数据；无数据/同日多记录/范围截断/非法工具/参数/超上限均受控；停止与跨入口删除正确。覆盖AC-05/06/09的数据链部分、AC-15/20。

### F02-P4：知识检索与来源闭环

1. 准备可信、可追溯文本语料及来源版本；实现受限文档导入和列表。
2. 实现标题感知切片、Embedding、索引任务和generation切换，串行化索引任务。
3. 实现active generation与删除状态权威过滤；失败清理可重试，旧索引仍可用。
4. 实现Retriever、Top-K、证据不足/检索故障分支，服务端citation映射和安全来源展示。
5. 用标注问题跑检索与引用评测，检查注入样本和关键结论证据。

退出：知识问题有真实来源；无证据不造引用；删除后不再检索，重建失败不破坏旧版，模型/维度变化重建完整空间。覆盖AC-07/08/19。

### F02-P5：组合分析和用户体验

1. 将个人数据、一般知识证据和不确定性分别组装，按问题路由，不无条件调用所有能力。
2. 统一步骤/工具/检索事件和预算，模型、检索、工具失败按既定规则终结或受控降级。
3. 完整工作流视图、来源状态、范围提示、记录趋势图、空状态及错误交互。
4. 完成正文/终态/引用持久化、刷新恢复、REST超时、切换会话对账及旧回调隔离。

退出：至少一条完整LangChain组合链贯穿报告确认后分析；停止、断流、刷新、知识不可用均有正确行为，缺失指标不补零。覆盖AC-09/10/11/14/18。

### F02-P6：正式验收与交接

1. 固定报告与知识集评测，分别报告首次/修复后通过率、字段准确率、缺失、工具选择和检索指标。
2. 模拟DB失败、tool chunks截断、静默上游、取消、背压、SIGTERM和崩溃重启。
3. 执行一期相关回归、全量离线测试、类型/构建，按变化补受控浏览器与子进程验证。
4. 少量必要真实调用使用合成/脱敏输入；不重复一期已接受的真实模型演练。
5. 交付演示脚本、验收结果、ADR、使用限制和下一阶段摘要。

退出：PRD AC-01…AC-21全部有证据；未通过项明确列出，不以Mock代替真实能力验收。因当前目标不含公网部署，交付仍是本机原型。

## 7. Codex开发token预算

这是二期未来开发、测试设计、失败分析、修复、回归与交接的规划估算，不是已发生用量；不含本次此前对话。当前没有完整开发会话的实测usage，输入反复携带上下文会显著影响总量，token不能只按最终代码字数估算。

下表单位M=百万tokens，输入含重复上下文的规划量；输出是预算估算，具体计费口径依实际服务usage。不能由可见文字推算不可观测内部消耗，不能把本表作为硬性账单上限。假设约180–280次有效模型交互，平均约25k–35k输入、1.5k–2.5k输出；阶段表为收敛后的工作预算，交互次数仅用于说明数量级。

| 阶段 | 输入M | 输出M | 合计M |
| --- | ---: | ---: | ---: |
| P0 | 0.40–0.80 | 0.025–0.050 | 0.425–0.850 |
| P1 | 0.70–1.20 | 0.050–0.090 | 0.750–1.290 |
| P2 | 1.00–1.80 | 0.070–0.120 | 1.070–1.920 |
| P3 | 0.80–1.40 | 0.060–0.100 | 0.860–1.500 |
| P4 | 0.80–1.50 | 0.060–0.100 | 0.860–1.600 |
| P5 | 0.70–1.30 | 0.050–0.090 | 0.750–1.390 |
| P6 | 0.60–1.10 | 0.040–0.070 | 0.640–1.170 |
| 合计 | 5.00–9.10 | 0.355–0.620 | 5.355–9.720 |

加20%余量：约6.43–11.66M，即约643万–1166万tokens，建议按640万–1170万规划。预算包含测试工作，不通过减少关键测试节省用量。重试、长期会话反复携带上下文、供应商兼容返工可能增加消耗；能拿到实际usage时每阶段记录输入/输出/缓存，拿不到则标“估算”，不伪造精确统计。

## 8. 应用模型测试、Embedding与费用口径

应用的DeepSeek/视觉/Embedding调用独立于Codex开发token，单独计账。离线单元、契约、Mock及类型构建不调用真实应用模型；重复运行离线测试不会产生这部分API token。

| 阶段 | 真实生成API调用预算（次） | 用途 |
| --- | ---: | --- |
| P0 | 30–50 | 新能力/边界及替代路径抽样 |
| P1 | 0 | 契约和设施使用Mock |
| P2 | 30–50 | 报告抽取与有限修复 |
| P3 | 40–70 | 单/多轮工具及参数选择 |
| P4 | 30–50 | 知识回答与引用；Embedding另计 |
| P5 | 30–50 | 组合链、取消和降级 |
| P6 | 60–90 | 固定集最终评测与必要重测 |
| 合计 | 220–360 | 计数单位是每次模型API请求，不是用户问题数 |

若平均每次生成请求文本输入4k、输出0.8k，则文本输入约0.88–1.44M、输出0.176–0.288M，合计1.056–1.728M；加20%余量约1.27–2.07M，即127万–207万文本tokens。真实工具多轮会重复发送历史，以上均按API请求计算，不漏算中间轮次。

首批知识语料假设5万–15万tokens，索引与重建共约2轮，Embedding基础0.10–0.30M，加余量约0.12–0.36M，即12万–36万tokens。超出语料规模需重估。图像/PDF/OCR费用受页数、分辨率、供应商影响，**不包含在上述文本token数**；暂按40–80份次报告识别请求准备量，P0确认识别路径后单列报价，不能把图片字数当token账单。

没有当前实际模型单价、缓存命中和结算方式，本轮不报固定人民币费用。API结算时，若I/H/O分别为百万输入/缓存输入/输出tokens，费用为 `(I-H)×未缓存输入单价 + H×缓存输入单价 + O×输出单价`；各模型分别计算，再加Embedding和图像/OCR、存储等实际收费。若服务没有独立缓存价，按其实际计价规则，不假定折扣；若使用订阅/额度而非API逐token结算，本估算不等同额外扣款金额。
