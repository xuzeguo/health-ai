## 安装与配置

在项目根目录执行：

```sh
nvm use
pnpm install
```

若不使用 nvm，请自行确认 `node -v` 为 22.x，且至少 22.12.0；本项目不会修改系统 Node 或其他项目配置。

复制 `.env.example` 为 `.env`，在本机填写 Key。已有 `.env` 不要覆盖；不要将密钥发到聊天或写入 `VITE_*`。骨架启动不会调用 DeepSeek，不消耗模型额度。

`.env` 位于仓库根，DB 路径以仓库根为基准，不随脚本工作目录变化。默认值：

```dotenv
DEEPSEEK_API_KEY=your_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
PORT=3000
DATABASE_URL=./data/health-ai.db
```

启动阶段会检查变量格式；占位 Key 只便于骨架启动，不代表真实调用有效。P2 的独立 Provider 脚本会拒绝占位 Key。

## 启动与验证

两个终端分别运行：

```sh
pnpm dev:server
```

```sh
pnpm dev:web
```

后端默认 `http://127.0.0.1:3000`；前端当前配置 `http://127.0.0.1:5188`。前端自动打开最近更新的会话（没有则创建），左侧可新建/切换/删除。发送时后端读取最近 20 条 completed 历史，排除本轮 user 后再追加本轮问题；前端只发送 conversationId 与本轮 message。已有历史以服务端 SQLite 为准；刷新打开最近更新会话，可从侧栏重新选择其他历史。

会话标题本期固定“新对话”，不生成自动标题；侧栏用更新时间与 ID 末四位辅助区分。删除当前会话后选取列表首项，删除最后一个后保留空态，再次发送可自动创建新会话。生成中点击新建/其他会话会先停止当前流并等待收尾，当前会话的删除按钮在生成时禁用。

```sh
pnpm check:scaffold
pnpm test
pnpm typecheck
pnpm build
pnpm verify:p6
```

`check:scaffold` 只检查工程结构，不代替安装、类型检查、浏览器或真实 HTTP 验收。`build` 输出前端产物；server 以 tsx 执行源码，shared 不单独构建。

`verify:p1` 在 P1 阶段串行运行结构、测试、构建和实际本机 HTTP 启动检查，生成脱敏 `docs/p1-smoke-result.json`。在禁止端口监听的执行环境中需要本机运行。该命令只适用于 P1 骨架（此时业务路由应返回 404），不代替后续业务验收。
